# Dev-Mode Security

The Docker Compose stack is a local developer bootstrap. It intentionally uses a
small set of unsafe conveniences so the foundation flow can run on a laptop.
Those settings must not be exposed to the Internet or copied into a production
deployment.

## Local-Only Flags

| Setting | Where | Local Purpose | Production Setting |
|---|---|---|---|
| `GO_BUILD_TAGS=dev` | gateway image build arg | Includes the local test-token bypass code path. | Build without `dev`. |
| `ARE_GW_DEV_UNSAFE_MODE=true` | gateway env | Enables local-only unsafe feature gates. | Unset or `false`. |
| `ARE_GW_ALLOW_INSECURE_TEST_TOKEN=true` | gateway env | Lets `Bearer test-token` work in local compose. The binary refuses this unless built with the `dev` tag and unsafe mode is on. | Unset; use real JWT/JWKS validation. |
| `ARE_GW_ENABLE_INSECURE_CONFORMANCE=true` | gateway env | Opens plaintext HTTP/gRPC conformance listeners for tests. It requires unsafe mode. | Unset; use TLS-only listeners. |
| `ARE_GATEWAY_METRICS_ALLOW_ANONYMOUS=true` | gateway env | Lets local Prometheus/manual checks scrape metrics without auth. | Unset; require auth or private network scrape only. |
| `POSTGRES_USER=are` / `POSTGRES_PASSWORD=are` | compose Postgres | Local demo database credentials. | Use managed secrets and non-default credentials. |
| `local-jwks` static nginx | compose service | Serves a local JWKS document for gateway tests. | Use a real identity provider/JWKS with key rotation. |
| generated `deploy/compose/tls/*` | generated by `make certs` | Local mTLS between gateway and BFF. Ignored by git. | Use managed certificates and rotation. |
| exposed OPA/Postgres/service ports | compose `ports` | Makes local debugging easy. | Do not expose internal dependencies publicly. |

## Guardrails In The Runtime

The gateway startup checks intentionally fail closed for the most dangerous
dev-mode combinations:

- `ARE_GW_ALLOW_INSECURE_TEST_TOKEN=true` only works in a binary built with the
  Go build tag `dev`.
- The insecure test token also requires `ARE_GW_DEV_UNSAFE_MODE=true`.
- Plaintext conformance listeners require `ARE_GW_DEV_UNSAFE_MODE=true`.
- Non-foundation routes fail closed at the gateway route guard.

These guardrails make local development easier without making the dev settings
look safe for deployment.

## What Not To Do

Do not:

- point public DNS directly at the Compose ports
- publish the generated TLS material
- reuse `test-token`
- leave anonymous metrics on for an exposed endpoint
- expose Postgres, OPA, JWKS, health, or BFF ports to the Internet
- store raw payloads, headers, signatures, credentials, or protected evidence in
  reports or examples

## Safer Demo Pattern

For a private external demo, put a real access layer in front of the frontend or
gateway, keep internal service ports private, and terminate TLS at a managed
edge. The OSS Compose file is still a local foundation runtime, not a public
hosting recipe.
